Tampilan Latency Deteksi & Mitigasi

Latency apa yang ingin ditampilkan, dan bagaimana tampilannya?

📐 Definisi latency yang bisa dihitung dari data yang ada:
⏱ Detection Latency
Stage 0 → Stage 1
~3 detik (rule-based fast path) atau ~3s (LSTM 3×window)
⏱ Confirmation Latency
Stage 1 → Stage 2
~5 detik (LSTM Stage2 window) atau langsung (rule fast-path)
⏱ Total Mitigation Time
Attack → Throttle Aktif
= Detection + Confirmation latency (~3–8 detik)

Stat Panels: Current Stage Duration

Dua stat baru di baris atas: "Stage 1 Active" (berapa lama warning berlangsung) dan "Stage 2 Active" (berapa lama critical berlangsung). Nilainya real-time countdown sejak stage berubah.

Pro

  • Langsung terlihat real-time saat demo
  • Butuh sedikit logic di exporter (track timestamp transisi)

Kekurangan

  • Reset ke 0 saat stage kembali normal — tidak ada histori
B

Tiga stat: "Detect Latency", "Confirm Latency", "Total to Mitigate" — nilai dari event terakhir (sticky, tidak reset saat normal).
