Pilih pendekatan implementasi

Tiga cara untuk menambahkan panel PRB + Mitigation Shading. Semua menghasilkan tampilan yang sama — bedanya di cara data ditarik.

A

⭐ Pakai xapp_detection_stage sebagai fill series (Rekomendasi)

Panel baru dengan 3 query: PRB DL, PRB UL, dan xapp_detection_stage yang di-scale dan dijadikan area fill. Stage 1 = kuning transparan, Stage 2 = merah transparan.

Queries di panel baru:
A: xapp_prb_dl_ratio
B: xapp_prb_ul_ratio
C: xapp_detection_stage / 2 (scale 0–1) → override: fill-below, opacity 20% → thresholds: 0.4=yellow, 0.9=red

Pro

  • Zero metric baru — pakai yang sudah ada
  • Hanya ubah 1 file: main.json
  • Tidak perlu rebuild exporter

Kekurangan

  • Shading = "detection stage" bukan "throttle aktif" secara harfiah (tapi identik secara praktis)
B

Grafana Annotations (vertical lines)

Tambahkan annotation query ke dashboard: deteksi kapan xapp_detection_stage naik ke 1 atau 2. Hasilnya garis vertikal di semua panel saat stage berubah.

Pro

  • Berlaku ke semua panel (PRB lama, LSTM, dll)
  • Garis "start" dan "end" jelas

Kekurangan

  • Kurang dramatis — garis tipis, bukan shading area
  • Perlu Grafana annotation API config
C

Metric baru xapp_throttle_active di exporter

Tambahkan Gauge baru di csv_exporter.py: set ke 1 saat stage2_confirmed == 1, 0 otherwise. Dipakai untuk shading di panel baru.

Pro

  • Semantically paling tepat: "throttle active" bukan "stage"
  • Bisa dipakai di panel lain juga

Kekurangan

  • Perlu edit 2 file: csv_exporter.py + main.json
  • Butuh rebuild exporter container
